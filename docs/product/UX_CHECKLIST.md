# UX Checklist

## Cel

Lista kontrolna UX dla KidZone. Uzywac przy zmianach funkcjonalnych, wiekszych zmianach ekranow oraz przed release.

## Pierwsze wrazenie

- [ ] Uzytkownik rozumie, do czego sluzy aplikacja.
- [ ] Glowne funkcje sa jasne: mapa, lista, ranking, profil, dodawanie miejsca.
- [ ] Onboarding nie jest zbyt dlugi.
- [ ] Onboarding da sie pominac.
- [ ] Po pierwszym uruchomieniu uzytkownik wie, co zrobic dalej.

## Nawigacja

- [ ] Dolna nawigacja jest czytelna.
- [ ] Ikony sa zrozumiale.
- [ ] Aktualny ekran jest wyrozniony.
- [ ] Uzytkownik moze latwo wrocic.
- [ ] Back behavior nie zaskakuje uzytkownika.

## Wyszukiwanie i filtry

- [ ] Wyszukiwarka jest latwa do znalezienia.
- [ ] Filtry sa opisane zrozumiale.
- [ ] Sortowanie jest intuicyjne.
- [ ] Brak wynikow ma empty state.
- [ ] Empty state zawiera sensowne CTA.

## Mapa

- [ ] Uzytkownik rozumie znaczenie markerow.
- [ ] Klikniecie markera jest przewidywalne.
- [ ] Bottom sheet pokazuje wlasciwe informacje.
- [ ] Brak lokalizacji ma czytelne wyjasnienie.
- [ ] Lista jest alternatywa dla mapy.

## Dodawanie miejsca

- [ ] Uzytkownik wie, ze FAB dodaje miejsce.
- [ ] Formularz jest podzielony logicznie.
- [ ] Pola sa zrozumiale.
- [ ] Bledy walidacji sa jasne.
- [ ] Po wyslaniu uzytkownik wie, co sie stalo.

## Ranking

- [ ] Uzytkownik rozumie, co oznacza ranking.
- [ ] TOP 3 jest wyroznione.
- [ ] Oceny i liczba opinii sa czytelne.
- [ ] Ranking nie wyglada jak tabela techniczna.

## Profil

- [ ] Profil jest czytelny.
- [ ] Statystyki sa zrozumiale.
- [ ] Pusty profil ma empty state.
- [ ] Edycja danych jest latwa do znalezienia.

## Komunikaty

- [ ] Komunikaty sa krotkie.
- [ ] Nie uzywaja zargonu technicznego.
- [ ] Mowia, co uzytkownik moze zrobic dalej.
- [ ] Sa przyjazne i konkretne.

## Manual UX test

- [ ] Uzytkownik znajduje miejsce bez pomocy.
- [ ] Uzytkownik dodaje miejsce bez pomocy.
- [ ] Uzytkownik rozumie ranking.
- [ ] Uzytkownik znajduje profil.
- [ ] Uzytkownik rozumie, co zrobic przy braku lokalizacji.
