# UI Checklist

## Cel

Lista kontrolna UI dla KidZone. Używać przy większych zmianach ekranów oraz przed release.

## Global UI

- [ ] Ekran używa wspólnego design systemu.
- [ ] Kolory są spójne z resztą aplikacji.
- [ ] Typografia ma poprawną hierarchię.
- [ ] Spacing jest zgodny ze skalą projektu.
- [ ] Cienie i radiusy są spójne.
- [ ] Ikony mają jeden styl.
- [ ] UI działa w jasnym i ciemnym motywie, jeśli oba są wspierane.

## Karty

- [ ] Karty są lekkie wizualnie.
- [ ] Tło kart nie jest zbyt ciężkie.
- [ ] Karta ma jasny tytuł.
- [ ] Rating jest czytelny.
- [ ] Adres i metadane nie dominują nad treścią.
- [ ] Długie nazwy mają fallback.
- [ ] Długie adresy mają fallback.

## Kategorie

- [ ] Kategorie są pokazane jako badge albo ikona.
- [ ] Kolor kategorii pomaga, ale nie krzyczy.
- [ ] Kolor nie jest jedynym nośnikiem informacji.

## Przyciski

- [ ] Primary action jest widoczna.
- [ ] Secondary action nie konkuruje z primary.
- [ ] Disabled state jest czytelny.
- [ ] Loading state przycisku jest obsłużony.
- [ ] Touch target jest wystarczająco duży.

## FAB

- [ ] FAB ma jasny kontekst.
- [ ] Użytkownik wie, że służy do dodawania miejsca.
- [ ] Pierwsze użycie jest wyjaśnione tooltipem albo onboardingiem.
- [ ] FAB nie zasłania ważnej treści.

## Formularze

- [ ] Pola mają etykiety.
- [ ] Błędy są widoczne przy polu.
- [ ] Walidacja jest zrozumiała.
- [ ] Klawiatura nie zasłania akcji.
- [ ] Submit jest blokowany podczas wysyłania.

## Release UI check

- [ ] Login wygląda poprawnie.
- [ ] Start wygląda poprawnie.
- [ ] Mapa wygląda poprawnie.
- [ ] Lista wygląda poprawnie.
- [ ] Ranking wygląda poprawnie.
- [ ] Profil wygląda poprawnie.
- [ ] Dodawanie miejsca wygląda poprawnie.
